# HoloNet managed janitor read mode

This default-off capability uses the existing laptop recommendation account and its existing private app-password file in place. It creates no account or credential copy. The separate native registration is holonet_janitor for Claude and Codex only.

The helper accepts only `holonet-janitor laptop`, on omarchy-macbook-air-igor UID 1001. It requests exactly `holonet.read holonet.janitor` from the existing fixed issuer/client/resource. It verifies RS256 and the closed flat managed-janitor contract: Movies library 3, empty catalog/history/target users, and exactly janitor.importers.read followed by janitor.custody.read. Mixed writer scopes, extra actions and private nested issuer metadata refuse.

Enable webmcp_interactive_holonet_janitor_enabled only with the existing writer capability enabled. The writer role performs its existing metadata-only credential checks; this mode neither reads the public cohort policy nor infers history or recipient authority from it. Existing catalog and recommendation registrations stay separate and unchanged.

Source support is not native qualification. Before enabling, require reviewed helper bytes, existing-account read enrollment in homelab-infra, canonical CHECK/REAL/repeat, then native tool discovery and the bounded importer canary. Do not invoke the helper manually, expose headers, or copy token caches. Rollback removes only the janitor registration and disables the flag; preserve the existing writer and its credential.

Radarr recycle is unconfigured. Importer-only bootstrap carries no filesystem mapping or custody source. No custody hashing, media removal, pause, schedule or Arr configuration write is enabled by this mode.
